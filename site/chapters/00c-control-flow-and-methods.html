Control flow and methods

Chapter 00b gave you values. This one gives you the four things you do with them: choose, repeat, name a piece of work so it can be reused, and hold many values at once. After this page you can read the code in every remaining chapter of this site.

Choosing: if

int age = 20;

if (age >= 18)                        // a condition — must produce a bool
{
    Console.WriteLine("Adult");        // runs only when the condition is true
}
else if (age >= 13)                   // checked only if the first was false
{
    Console.WriteLine("Teenager");
}
else                                  // everything the tests above did not catch
{
    Console.WriteLine("Child");
}
Line by line
  • if — a keyword introducing a conditional statement.
  • (age >= 18) — the condition, and the parentheses are required. It must be a bool. Unlike C or JavaScript, C# will not accept a number or an object here — if (5) does not compile, and neither does if (name).
  • { … } — the block that runs when the condition holds. Braces are optional for a single statement and you should write them anyway: adding a second line later without adding braces is a real and famous class of bug.
  • else if — not one keyword but two: an else whose body is another if. Order matters, and only the first matching branch runs. Had the >= 13 test come first, no one would ever be "Adult".
  • else — the fallback. Optional. It has no condition because it is everything left over.

Choosing between many: switch

string status = "Shipped";

string message = status switch          // a switch EXPRESSION: it produces a value
{
    "Draft"     => "Not sent yet",       // pattern => result, comma separated
    "Shipped"   => "On its way",
    "Delivered" => "Arrived",
    _          => "Unknown status"      // _ is the catch-all, like else
};                                     // semicolon: this whole thing was one statement
Line by line
  • status switch — a switch expression. Note the order: the value comes first, then the keyword. It evaluates to a value, which is why it can sit on the right of an =.
  • => — here it separates a pattern from the result for that pattern. (The same arrow means "goes to" in a lambda, which you will meet in chapter 06. Same symbol, different job.)
  • _ — the discard pattern: matches anything. It is the else of a switch expression.
  • }; — a closing brace and a semicolon, because the whole switch was part of an assignment statement. Forgetting the semicolon here is a very common early error.
  • Exhaustiveness is the reason to prefer this over a chain of ifs: with an enum, the compiler warns when you have missed a case. An if/else if chain never tells you what you forgot.

Repeating

for (int i = 0; i < 3; i++)          // start; keep going while; after each pass
{
    Console.WriteLine(i);            // prints 0, then 1, then 2
}
Line by line
  • for — three clauses separated by semicolons, not commas.
  • int i = 0 — the initialiser. Runs once, before anything. i exists only inside the loop.
  • i < 3 — the condition, tested before every pass including the first. It is < and not <= because counting from 0 for three items means 0, 1, 2 — writing <= here is the classic off-by-one error.
  • i++ — the iterator, run after each pass. Leave it out and the loop never ends.
  • Starting at 0 is not a style choice — collection positions in C# begin at 0, so the first item is [0] and the last is [Count - 1].
string[] cities = { "Modena", "Bologna", "Parma" };

foreach (string city in cities)      // take each item in turn
{
    Console.WriteLine(city);        // no index, no counter, no off-by-one
}
Line by line
  • foreach — loops over the items of a collection directly. Prefer it: it cannot run off the end, and it says "for each of these" rather than "count to a number and use it to look things up".
  • string city — declares the loop variable, a fresh one per pass, holding the current item.
  • in — a keyword, part of the foreach syntax.
  • You cannot add to or remove from a collection while foreach is walking it. Doing so throws InvalidOperationException at run time. Collect what you want to change and act after the loop.
int attempts = 0;

while (attempts < 3)                 // test FIRST, so it may run zero times
{
    attempts++;
    if (attempts == 2) continue;      // skip the rest of THIS pass
    if (attempts == 3) break;         // leave the loop entirely
}
Line by line
  • while — repeats while a condition holds, testing before each pass. Use it when you do not know the number of passes in advance.
  • continue — abandons this pass and goes to the next. In a for loop the iterator still runs, which matters: a continue placed before i++ in a while loop is an infinite loop.
  • break — exits the loop completely. It affects only the innermost loop it sits in.
  • do { … } while (…); — the variant that tests after, so the body always runs at least once. Rare, and it takes a semicolon at the end.

Methods: naming a piece of work

static decimal AddVat(decimal net, decimal rate = 0.22m)
{
    return net * (1 + rate);        // hand the answer back and stop
}

decimal a = AddVat(100m);           // 122.00 — rate defaults to 0.22
decimal b = AddVat(100m, 0.10m);    // 110.00 — the default is overridden
decimal c = AddVat(rate: 0.04m, net: 100m);  // 104.00 — named, so order is free
Line by line
  • static — belongs to the type rather than to an object of it. In a top-level Program.cs your helper methods need this.
  • decimal (the first one) — the return type: the kind of value this method hands back. void would mean it hands back nothing.
  • AddVat — the method name, PascalCase by convention, and a verb because a method does something.
  • (decimal net, decimal rate = 0.22m) — the parameter list. Each parameter is a type and a name. A parameter is the name inside the method; the value passed in at the call is the argument.
  • rate = 0.22m — an optional parameter with a default. Optional parameters must come after all required ones.
  • return — produces the value and exits the method immediately. Anything written after it in the same block is unreachable, and the compiler will say so.
  • AddVat(100m) — the call. Control jumps into the method, runs it, and the call expression becomes the returned value.
  • rate: 0.04m — a named argument. It frees you from the declared order and, more usefully, makes the call site readable: Send(retry: true) beats Send(true).
static bool IsEven(int n) => n % 2 == 0;   // expression-bodied: one expression, no braces

static void Greet(string who)             // void: does something, returns nothing
{
    Console.WriteLine($"Ciao, {who}");
}                                          // no return needed
Line by line
  • => n % 2 == 0; — an expression-bodied member. Shorthand for a body that is a single expression; the value of that expression is returned, so no return keyword appears. Identical to the braced form once compiled.
  • void — returns nothing, so it is called as a statement on its own line and cannot appear on the right of an =. A bare return; is still legal inside one, to leave early.
  • Overloading — several methods may share a name if their parameters differ. That is why Console.WriteLine accepts a string, an int or an object: those are different methods with one name.

Holding many values

string[] fixedSize = new string[3];      // an ARRAY: length 3, forever
fixedSize[0] = "Modena";                  // positions start at 0
int n = fixedSize.Length;                 // 3 — array uses Length

List<string> growable = new();           // a LIST: starts empty, grows
growable.Add("Bologna");                  // append one
growable.Add("Parma");
int m = growable.Count;                   // 2 — list uses Count, not Length
string first = growable[0];              // "Bologna" — same square brackets
Line by line
  • string[] — "array of string". The square brackets are part of the type.
  • new string[3] — new creates the object; [3] is the length, fixed for its whole life. The three slots start as null, and for an int[] they would start as 0.
  • fixedSize[0] — the indexer. Positions run 0 to Length - 1; fixedSize[3] throws IndexOutOfRangeException at run time.
  • List<string> — a generic type. The <string> is a type argument saying what it holds, and it is why growable[0] is known to be a string with no cast. You will meet generics properly in chapter 04.
  • new() — a target-typed new. The type is already written on the left, so C# lets you not repeat it. The long form new List<string>() is identical.
  • .Length versus .Count — arrays have Length, lists have Count, and strings have Length. There is no logic to memorise here; it is simply history, and mixing them up is a compile error rather than a bug.

Classes and objects, in sixty seconds

You have enough now to read most code, except for the one shape everything in C# is packaged into. Chapter 03 is the real treatment; this is only enough to make the next chapter readable. 

public class Customer                       // a TEMPLATE — describes what a customer has
{
    public string Name { get; set; } = "";   // a property: data with a door on it
    public int Orders { get; set; }

    public bool IsLoyal() => Orders > 10;  // a method: behaviour, using its own data
}

Customer c = new() { Name = "Rossi", Orders = 12 };  // an OBJECT, made from the template
Console.WriteLine(c.IsLoyal());                     // True
Line by line
  • class Customer — declares a type. A class is a template, not a thing: no customer exists yet, in the same way a blueprint is not a house.
  • public — an access modifier: visible everywhere. Its counterpart private means "only inside this class" and is the default when you write nothing.
  • { get; set; } — an auto-property. It looks like a field but is really a pair of hidden methods, so the class can later add a rule to set without a single caller changing. That is why C# code exposes properties and not raw fields.
  • = ""; — an initialiser, so Name starts as an empty string rather than null.
  • IsLoyal() — a method that reads Orders without any prefix, because inside the class it means "this object's Orders".
  • new() — creates an instance. The class is the template; this is one actual customer, with its own values.
  • { Name = "Rossi", … } — an object initialiser: set properties as part of construction. Commas between, not semicolons.
  • c.IsLoyal() — calls the method on that object, so Orders inside it means 12.
Try it yourself

Write a program that asks for numbers one at a time until the user types an empty line, then prints how many were entered, their total, and their average. You will need a while loop, TryParse from 00b, a List<decimal>, and one decision about what to print when the list is empty — because dividing by Count when Count is zero is your first DivideByZeroException.

Golden rules

  1. A condition must be a bool. C# does not accept a number or an object where a truth value belongs, and that is a feature.
  2. Always write the braces, even for one statement. The bug arrives when somebody adds the second statement.
  3. Only the first matching branch of an if/else if chain runs. Order the tests from most specific to least.
  4. Prefer a switch expression over a long if chain: with an enum the compiler tells you which case you forgot.
  5. Indexes start at 0 and end at Length - 1. Use < in a for, not <=.
  6. Prefer foreach to for when you do not need the index — it cannot run off the end.
  7. Never add to or remove from a collection you are currently foreach-ing.
  8. return exits the method there and then.
  9. Arrays are fixed length and use Length; List<T> grows and uses Count.
  10. A class is a template; an object is one thing made from it. Expose properties, not fields, so a rule can be added later without breaking callers.

Interview questions

"When would you use a switch expression over if/else?"

When you are choosing a value from a set of mutually exclusive cases. It is an expression, so it can be assigned or returned directly, and over an enum the compiler warns about unhandled cases — exhaustiveness an if chain can never give you.

"What is the difference between an array and a List<T>?"

An array has a fixed length chosen at creation; a List<T> wraps an array and grows by allocating a bigger one and copying when it fills. Use an array for a fixed-size buffer or a hot path, a list for anything whose size you do not know up front. And it is Length on one, Count on the other.

"What is the difference between a parameter and an argument?"

A parameter is the variable declared in the method signature; an argument is the actual value passed at the call site. The distinction matters as soon as you discuss ref, out and pass-by-value, because those are all statements about how an argument reaches a parameter.

"Why do C# classes expose properties instead of public fields?"

A property is a pair of methods behind field-like syntax, so validation, laziness, change notification or logging can be added later without any caller changing or even recompiling against a different shape. A public field is a permanent commitment to raw access, and data binding and many serialisers only look at properties anyway.
