Sign in

You do not need an account to use this site — every chapter, every test and every note already works, saved in this browser. Signing in does exactly two things: it carries that progress from a laptop to a phone, and it lets more than one person share a machine or a deployment without overwriting each other.

🧒 What a login really is

The server does not remember you. Every request has to prove who it is on its own, the way a wristband at a theme park does — nobody at the ride remembers you buying a ticket, they just look at your wrist.

When you sign in, the server gives you two things. A wristband that works for fifteen minutes, and a ticket stub you keep in your pocket to swap for a fresh wristband when the old one runs out. If somebody steals the wristband it stops working almost immediately; the stub can only be used once, so if it is used twice the server knows something is wrong and cancels everything.

🎓 What this form actually does

It POSTs to /api/auth/login on LogiFlow.Academy.Api and gets back an access token (a short-lived JWT, sent on every later request as Authorization: Bearer …) and a refresh token (long-lived, stored only as a SHA-256 hash server-side, single-use, and rotated on every exchange). Presenting an already-exchanged refresh token revokes the whole family, because the server cannot tell a replay attack from a client that lost the response to its own refresh — and of those two, only one is safe to guess wrong.

Your password is never stored. It is run through PBKDF2 with a per-user salt, and the iteration count is upgraded transparently on your next successful sign-in — that moment is the only time the plaintext is legitimately available to re-hash. ⚠ Why the error message is deliberately unhelpful

A wrong password and a username with no account here produce the identical message and take the identical amount of time. That is not laziness. “No account with that username” turns a login form into an account-enumeration oracle: anybody can test a list of names and learn which ones are registered, which is half of credential stuffing.

Constant message and constant work — the server burns the same CPU verifying a password that does not exist, so response time gives nothing away either. Eight failed attempts lock the account for fifteen minutes, and that lock is reported, because by then the caller already knows the account exists.

The recovery page is careful in exactly the same way, and for a sharper reason: it is the one form that can be probed with a username and no password at all. Registration is the deliberate exception — it tells you plainly that a username is taken, because a username is printed on the leaderboard and hiding it would only leave people guessing why signing up failed.
